# 図の見本集
図は、論点の種類から形を決め、見本を写して中身を替えて描く。形をその場で考えると、同じ論点でも資料ごとに描き方が変わり、読み手が毎回読み方を覚え直すことになるため。

見本は `samples/<分類>/<名前>.svg`、一覧で見比べるときは [catalog.html](catalog.html) を開く。各 SVG の `<desc>` に「形・使う場面・使わない場面」が書いてある。

この skill は ja-writing に入れず分けている。ja-writing は日本語の文の決まりで、図は artifact・設計書（dev-docs）・スライド・提案資料のどれでも使うため。文書のどこに図を置くか（各論は図と 1 行で始める、人が読む文書は .svg ファイルで置く、mermaid を使う場面）は ja-writing が決め、ここはどの形で描くかを決める。

# 形の選び方
論点で答えたい問いから行を選び、その行の見本を写す。迷ったら、各見本の「使わない場面」に書いてある別の形と比べる。

| 問い | 中身 | 見本 |
|---|---|---|
| 何がどの順に起きるか | 分岐のない手順 | `flow/steps` |
| | 条件で分かれる手順 | `flow/flowchart` |
| | 担当ごとの受け渡し | `flow/swimlane` |
| | システム間のやり取りの順番 | `flow/sequence` |
| | データの出どころ・保存先・届け先 | `flow/data-flow` |
| | 何度も回す仕事 | `flow/cycle` |
| | 許可を得ないと進めない手順 | `flow/gate` |
| | 順に試す手段 | `flow/fallback` |
| | 段階ごとに減る件数 | `flow/funnel` |
| 1 つのものがどう移り変わるか | 状態と、移るきっかけ・戻り道 | `state/state-machine` |
| | 戻りのない一生 | `state/lifecycle` |
| | 状態ごとの件数と滞り | `state/status-board` |
| 何が何でできているか | 上下に積む層 | `structure/layers` |
| | 分類と内訳 | `structure/tree` |
| | 包み合う範囲 | `structure/nested` |
| | 1 つが周りを束ねる | `structure/hub-spoke` |
| | 画面のどこに何を置くか | `structure/screen-grid` |
| どちらを選ぶか、何が変わるか | 変える前と後 | `compare/before-after` |
| | 2〜4 案から選ぶ | `compare/option-table` |
| | 多くの候補を 2 つの観点で仕分ける | `compare/matrix-2x2` |
| | 1 案を採るかどうか | `compare/pros-cons` |
| | 程度の段階から選ぶ・今と目標 | `compare/spectrum` |
| いつ何が起きる・起きたか | 済んだ経緯 | `time/timeline` |
| | 先の予定と担当 | `time/gantt` |
| | 節目と通過の条件 | `time/milestones` |
| | 週の定例と締切 | `time/week-rhythm` |
| 誰と何がどうつながるか | 前後関係と、詰まると止まる道 | `relation/dependency` |
| | 誰が担当し誰が決めるか | `relation/raci` |
| | 誰が何を読み、何を書くか | `relation/read-write` |
| | 元がどこへ配られるか | `relation/wiring` |
| | 範囲の重なりと差 | `relation/venn` |

数値の推移・比較・内訳の大きさ・分布はグラフにし、dataviz skill に従う。見本の中に件数を書くもの（絞り込み・木・状態ごとの件数）は、件数を読ませるのではなく、形の上での位置を見せるときに使う。

# 描き方
1. 見本の SVG を丸ごと写し、文字を替える。`<title>` は図の名前、`<desc>` は消すか図の説明に書き替える
2. 箱の幅を文字に合わせる。日本語 1 文字は文字の大きさとほぼ同じ幅（13px なら 13px）、英数字はその 0.6 倍で数え、左右に 8px 以上の余白を残す。足りなければ箱と viewBox を広げ、文字を小さくしない
3. 色は意味ごとに 1 つずつ当てる。見本では、青（`a`）が主役やおすすめの案、黄土（`b`）が顧客や人の判断、緑（`c`）が良くなる点や置き場所、赤茶（`w`）が困りごとや止まる所。色を使ったら図の下か本文に凡例を書く
4. 図の単位（何が 1 つの箱か）を凡例か見出しで言い切る。元の資料の図を写さず、論点に合う形を選び直す
5. 入れ子になる単位（クラウドのアカウント・テナント・会社）は、外側を太い枠と上の帯にして、帯に単位の名前を書く。灰色の塗りの箱を置くだけでは、それが何の単位かが伝わらない（AWS の構成案の資料で「灰色のやつが 1 アカウントって単位なのが全然伝わらない」と直されたことがある）
6. 同じ種類のもの（6 つの環境など）は同じ見た目・同じ寸法にし、行と列の座標をそろえて格子に並べる。差の無いところに見た目の差を作ると、読み手は差があると受け取る。部品を図の下に一列に並べて終えず、どこにつながるかを線で描く
7. 仕組みを説明する図は、工程名を並べただけで終えない。工程ごとに「何をするか 1 文・使うもの・具体例 1 件がどう変わるか」を縦にそろえて書く（資料のリポジトリに入出力つきの工程の雛形があれば、それを使う）
8. 描いたら画像として開き、重なり・はみ出し・読めない文字がないか見る。明るい画面と暗い画面の両方で見る
9. 提案資料・設計書など社外に出す図と、窓の画面の図は、8 で撮った画像（PNG）を Neon にも見せる（深田が内部で見る artifact の図は 8 の確認だけでよい）。学習の系統が違う目のほうが、描いた本人が見慣れて見落とすずれを拾う。聞くのは重なり・はみ出し・読めない文字・色の区別だけにし、好みは聞かない
   ```bash
   python3 -I ~/.config/agent-harness/claude/bin/agy_launch.py agy --model gemini-4-neon-high --print-timeout 120s --add-dir <画像のフォルダ> -p "<画像の絶対パス> を開き、重なり・はみ出し・読めない文字・色で区別できない所だけを、場所を添えて挙げて。無ければ「なし」"
   ```
   agy は agy_launch.py から起こす（環境変数を絞り、Claude Code から起動された文脈を渡さない、R29。Gemini 以外のモデルは断る、R108）。agy は Google に通信するので、Claude の sandbox の中（worker など）では動かない。そのときは窓口に頼む。agy が `--add-dir` の画像を読めるかは確かめていない
10. artifact・HTML のページに置く図は、見出し・文章・表と同じ 1 つの列に、列の幅いっぱいに置く。図だけを狭い max-width の枠に入れない。決まりは ja-writing の references/pages.md の「ページの幅」

## 見た目の決まり
少ない決まりでそろえると、図が資料の中で 1 つの系統に見える。色を塗る範囲を絞り、主役を 1 つに決めてから描く。

| 何を | 決まり | クラス |
|---|---|---|
| 色を塗る | 枠と面の両方に色を付けるのは主役の箱だけ（`fa`・`fb`・`fc`・`fw`、線 1.25）。範囲や列を色で示すときは枠なしの面（`pa`・`pb`・`pc`・`pw`）にし、見出しの文字を同じ色（`ta`・`tb`・`tc`・`tw`）にする。外枠と中の箱を両方色付きにしない | |
| 線 | 普通の箱 1、色付きの箱 1.25、罫線・格子・区切り 1、木やハブのつなぎ線 1.5（枠より少し濃い `--dg-link`）、矢印 1.5、要の道 2（青）。止まる・戻る道は赤茶の 1.5 | `box` `ln` `cn` `ar` `em` `ew` |
| 点 | 軸や散布の上の印は半径 4〜7。おすすめのものは色で塗り（`dot`・`fa` など）、ほかは白抜き（`ring`、枠は補足色 1.5）にして、軸の線より印を前に出す | `dot` `ring` |
| 破線 | `4 4`。戻り・読むだけ・コピー・境界のように意味があるときだけ使う。表の行の区切り・引き出し線・うまくいった道は実線 | `dash` |
| 角丸 | 箱 6、小さなラベル・棒 4、外側のまとまり（列・枠・帯）8、始まりと終わりはカプセル（高さの半分）。直角に折れる矢印の角は 4（`Q` で丸める）。木の枝分かれのような T 字は直角のまま | |
| 文字 | まとまりの見出し 16/600、箱の見出し 14/600、本文 13/400、補足・目盛り 12/400、番号 12/600。行送りは本文 20、補足 18。文字は回さず、縦の軸の名前は 1 字ずつ縦に積む。数の列は右揃え | `g` `h` 無印 `s` `n` |
| 矢じり | 長さ 8・幅 6 の三角を `markerUnits="userSpaceOnUse"` で固定し、色は線に合わせる（`fill:context-stroke`）。線を太くしても矢じりは大きくならない | `tip` |
| 間隔 | 4 の倍数。箱の中の左右 12〜16、上下 12、つながる箱の間 24〜32、まとまりの間 32〜48、ラベルと線の間 8 | |

見本を足す・直すときは、幅を 560 にそろえ、catalog.html を上の「形の選び方」の表と同じ順に並べる（表から引く人が同じ順で探せるように）。

## 色とテーマ
見本の `<style>` の `/* base */` 〜 `/* /base */` は、[base.css](base.css) を `build_catalog.py` が書き写したもの。色は `--dg-*` の変数で受け、決まっていなければ見本の中の値（暗い画面では暗い画面用の値）を使う。

- `.svg` ファイルとして `![]()` や `<img>` で置くと、閲覧者の OS の明暗に合わせて切り替わる
- artifact や HTML のページに `<svg>` を直に書くときは、ページ側の配色トークン（明るい画面・`prefers-color-scheme: dark`・`[data-theme="dark"]` の 3 か所）に `--dg-bg` `--dg-ink` `--dg-sub` `--dg-line` `--dg-link` `--dg-soft` `--dg-a` `--dg-a-bg` `--dg-b` `--dg-b-bg` `--dg-c` `--dg-c-bg` `--dg-w` `--dg-w-bg` を足す。書き方は catalog.html の先頭の `<style>` をそのまま写す。足さないと、ページのテーマ切り替えに図が付いてこない
- 1 枚のページに見本を何枚も直に書いても、共通のクラスは同じ定義なのでぶつからない。見本ごとの追加の CSS（アニメーションなど）は、別の図と同じクラス名にならないよう名前を替える
- 矢じりの marker は全見本で同じ定義の `id="dg-tip"` を使い、ページに直に書くと、最初の定義が使われる。矢じりの色は線の色に付いてくる（`context-stroke`）ので、線の色を変えても marker を分けなくてよい

## 動かすとき
ユーザーが動きを求めたときに、順番が読み手に要る図だけを動かす。決まりは ja-writing の references/pages.md「順序や流れが読み手に要る図」に従う（止まった状態で読めること、`prefers-reduced-motion` で止めること）。見本では `flow/steps`・`flow/sequence`・`flow/data-flow` が動く。

`animation` の一括指定は、あとから足す `animation-delay` を打ち消すことがある。見本のように `animation-name` と `animation-duration` を分けて書き、箱や矢印ごとに `animation-delay` だけをずらす。確かめるときは `document.getAnimations()`（直に書いた SVG）か `要素.shadowRoot.getAnimations()`（catalog.html）で時刻を止め、箱や矢印が 1 つずつ順に光るかを見る。

# 見本を足す・直す
1. `samples/<分類>/<名前>.svg` を書く。ルートの `<svg>` に `class="dg"` と viewBox を付け、`<title>` を置き、`<desc>` に「形:」「使う場面:」「使わない場面:」の 3 行、`<style>` の先頭に `/* base */` と `/* /base */` の 2 行を書く（中身は次の手順で入る）
2. `python3 build_catalog.py` を流す。base.css を全見本に書き写し、形式を確かめて catalog.html を作り直す。足りないものがあると、ファイル名と理由を出して止まる
3. カタログでの並びは `build_catalog.py` の `CATEGORIES` に書く。書かなかった見本は分類の最後に名前順で並ぶ。新しい分類のディレクトリを作ったら `CATEGORIES` にも足す
4. この SKILL.md の「形の選び方」の表に行を足す
5. catalog.html をブラウザで開き、明るい画面と暗い画面で見る。一覧では動く見本も最初の場面で止まり、図を押して開いた拡大表示でだけ動く
6. `python3 build_catalog.py --check` で、書き写しとカタログの作り直しが済んでいるかを確かめる（何も書かず、古いファイルがあれば一覧を出して 1 で終わる）

配色を変えるときは base.css だけを直して `build_catalog.py` を流す。見本の SVG と、カタログのページ側の `--dg-*` の両方が base.css の値で作り直される。カタログの見た目（カードの並び・余白）は catalog.template.html にある。
