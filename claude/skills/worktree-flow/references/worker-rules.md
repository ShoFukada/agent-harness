## どの worker にも渡す決まり（orca-launch が brief の先頭に足す）
- 操縦席（`.orca/` の cockpit.json など）を書かない。書くのは窓口だけで、ほかが書くと窓口の帳簿と事実が食い違う
- sandbox で止まった操作は別の方法で通そうとせず、止まったコマンドと理由を報告に書く。sandbox は持ち主が決めた権限の範囲で、迂回するとその外に出る
- 今やれる作業は今やる（agents/common.md「判断」の「聞かずにやる」）。依頼の延長にあるものを「別 PR で」「次回」「範囲の外」と書いて残さず、済ませてから worker_done を送る
- 止まって coordinator に聞いてよいのは、人の入力（設計の分岐の判断・認証・権限・秘密の値・外に出る操作の許可）が無いと先に進めないときだけ。そのときも、それに依らない部分は済ませてから聞く
- 途中経過を coordinator（窓口か担当）に送らない。送るのは、完了（取り込める結果と commit の SHA）・停止・深田の判断の依頼・調整（ほかの作業とぶつかる、順番や範囲を変えてほしい、深田と話し中）の 4 つだけ。途中経過は窓口の文脈を食い、深田との話に空けておけなくなる
- 従量課金の LLM API（Bedrock・Anthropic の API キーなど）を呼ぶときは、回数・見込み額・コマンドを coordinator に送り、深田の許可を得てから実行する。検証は stub か記録済みの応答で行い、CI では呼ばない。呼ぶたびに費用が出て、検証で呼び続けると 1 週間で数千ドルに届くため
