# 依頼の受付と仕分け

cockpit skill の SKILL.md から分けた手順。深田に話しかけられたターンに、仕分けていない発言（state.ts の `checks.unsorted`）があるとき、依頼の済を証拠に結ぶときに読む。帳簿の欄は references/schema.md の「依頼の帳簿」。

# 受付と仕分け
深田の依頼は、受けた時点で依頼の帳簿（`requests[]`）に載せ、済の証拠がそろうまで消さない（R33）。欄と規則は references/schema.md の「依頼の帳簿」。
- hook が深田の発言を `utterances.jsonl` に id（`u-<行番号>`）付きで残す。Orca の知らせは記録されない
- 窓口は、深田に話しかけられたターンのうちに、まだ仕分けていない発言（state.ts の `checks.unsorted`）を 1 つずつ次のどれかにして、書く道具で書く。1 つの発言に 2 件の依頼があれば 2 件起こし、それぞれに引用の範囲を書く
  - 新しい依頼: `requests[]` に `utterances`（id と引用）・`kind`・`done_when`（済の条件 1〜3）・`check` を書いて足す
  - 既存の依頼への追記・返答: その依頼の `utterances` に足す（「直して」「それで」も、どの依頼への返事かで結ぶ）
  - 依頼でない（相づち・「ok」・お礼）: `intake.none` に足す
  - 終えたら `intake.through` をその発言の id に進める。仕分けていない発言をまたいでは進められない
- 語尾や疑問符の有無で依頼でないと決めない（2026-11-21 の「操縦席のみてのところクリックできない」は疑問符も依頼の語尾も無い依頼だった）
- 済は窓口が書かない。作業が済んだら、済の条件ごとに証拠（main に入った commit・マージした PR・公開した URL・結論と根拠を書いた回答・深田の操作）を `evidence` に結ぶと、state.ts が済にする。質問・調べものは、結論と根拠を結んだ回答で済にしてよい（R47）。深田の確認が要るもの（`check: true`）は、今の版の確認に「承認」が押されるまで済にならない
- 仕分けていない発言が残ったままターンを終えようとすると、Stop の hook が 1 回止める
- 窓口が自分で引き受けた仕事（「〜しておきます」「直します」と返したもの）も依頼として受ける。新しい種類は作らない。既存の依頼の続きならその依頼の `done_when` に足し、新しい仕事だけ新しい依頼にして `source` に窓口の返事の原文を書く。返事を出す前に、引き受けた項目をそれぞれ依頼かタスクに結ぶ（11/21 に、窓口が引き受けた直しが帳簿に載らず抜けた。台帳の B035）
- 範囲の外で気づいたこと: 伝えるだけのものは報告で閉じる。直すものは既存のタスクに、許可が要るものは許可のカードに結ぶ。言い回しで約束を拾う hook は作らない（hook が止めるのは、未仕分けの発言・承認の取り込み漏れのように、欠けた対象を名指しできるときだけ）。都合での先送りの言い回し（「12 月に」「落ち着いてから」「別 PR で」）だけは、約束を拾うのでなく先送りを止めるために、Stop の hook と worker_done の送信前の hook（defer-guard.py）が 1 回差し戻す（R193）
- 担当・worker への brief には、そのタスクを `tasks[]` に持つ依頼の済の条件（依頼の id・番号・本文）を入れる（`orca-launch --cockpit-task` は自動で末尾に足す）。戻りは、worker の報告の「仮定」からではなく、済の条件を起点に証拠を照合する。条件を変えて済ませたものは、そのまま済にせず判断に回す。タスクが全部済なのに証拠の無い済の条件が残る依頼は `checks.unproven` に出る（11/21 に、worker が条件を変えて済ませた依頼がそのまま済に見えた。台帳の B025）
