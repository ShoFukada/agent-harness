# 判断の記録の欄と書き方

cockpit skill の SKILL.md の「判断の記録」から分けた決まり。いつ書くか・`compaction-keep.py rule` に渡す JSON・撤回と置き換え・コマンドに断られたときの直し方を持つ。決めたとき、判断を記録するときに読む。

## いつ書くか
自動圧縮を何十回重ねても決定・制約・許可・却下の理由を落とさないよう、決めた時点で会話の外の `.orca/cockpit/rulings.jsonl` に 1 行書く。圧縮のあとは hook が有効な判断を原文で流し直し、要約には写させない（同じチャットで何日も続けるため。週ごとにチャットを切り替える運用は採らない）。

書くとき:
- 範囲・届け先・対象を変える判断では、影響する既存のタスク（済も含む）を `affects` に挙げる（欄の決まりは下の表のあと）
- 判断・許可・選択肢のある送信前のカードが done になったとき（深田の決定を反映した直後）。残す判断が無いカードも `kind: "none"` でカードの id を `dec` に書く（Stop の hook が、記録の無い済んだカードを名指しする）
- 深田が「この案件では一任する」（`delegate`）を押したとき: `kind: "permission"`・`scope` にカードの `scope`・`allow: true` で書く
- 深田の発言に許可・禁止・撤回が含まれるとき（「dev には入れていい」「push はしないで」「やっぱり待って」）。Stop の hook が、言い回しが当たったのにそのターンで記録していないと 1 回止める。判断でなければそう一言書いて終える
- 案を比べて退けたとき（却下した案と理由）

```bash
~/.claude/hooks/compaction-keep.py rule <ワークスペースの root> <<'JSON'
{"kind": "permission", "text": "dev への反映はメインの判断で進めてよい", "scope": "dev への反映", "allow": true,
 "quote": "dev には入れていいよ", "dec": "d51"}
JSON
```

kind ごとの要る欄、撤回と置き換えの書き方、有効な判断の一覧の出し方は下に書く。記録したら、下の「決めたとき」で置き場所を直す（案件の中だけの許可は記録だけで済む）。
- 有効な制約（`constraint`。「返事は日本語」の R55 など）は、セッションの開始・再開のたびに hook が原文で流し直す（圧縮のあとは有効な判断を全部流す）
- 作業メモ（state.md）では、判断の中身を写さず ID（R12）で指す。カードの文には番号を書かず、要る中身を平文で 1 文書く（窓から判断の記録を開けないため。references/cards.md の「窓に出す情報」）
- 担当・worker への brief には、その作業に関わる判断の本文と原文（`rulings` の出力の行）をそのまま書く。担当と worker はこの記録を読む手段を持たず、ID だけでは制約が届かない

## 決めたとき
決めたことが、それを守らせる文書・雛形・道具のすべてに届くようにする手順。直し忘れを検査で探すのではなく、写しを無くして防ぐ。
1. 案件の中だけの許可・判断（この案件の push の一任など）は、その案件の rulings.jsonl に残すだけにし、置き場所の文書は直さない。文書が「一任されていれば出さない」のように記録を引く形になっていることだけを確かめる。複数の案件にかかわる運用の変更だけ、2 から先をする
2. CLAUDE.md の「決まりの置き場所」で領域を引き、その置き場所だけを直す。直した置き場所は判断の記録の `paths` に書く
3. 置き場所の外に同じ決まりの写し（値の一覧・手順の要約・古い名前）を見つけたら、置き場所に寄せ、写しは置き場所の節を指す 1 行に替える。読む人が 1 回で辿れるよう、節の名前まで書く
4. 形で決まるもの（名前の形・工程名・カードの種類・必須の欄）は、入口の道具のコードを直す。文書には値を写さない。雛形（`template.json`）は正しい入力例として合わせる
5. 複数の案件・入口にかかわる判断は、担当・worker に出す依頼の完了条件に「誰が・どの入口から始めて・何ができるか」を書く（例: 新しい案件の窓口が references/setup.md だけを起点に「社内｜<案件>」と名付けられる）
6. 実装（state.ts・account-failover・automation）を変える判断は、その置き場所の文書も同じ依頼の完了条件に入れる

| kind | 何か | 要る欄 |
|---|---|---|
| `decision` | 決まったこと | `text` |
| `constraint` | 守る制約 | `text`・`quote`（深田の発言の原文） |
| `permission` | 許可・禁止の範囲 | `text`・`quote`・`scope`（対象）・`allow`（true が許可・false が禁止） |
| `rejection` | 却下した案 | `text`（理由）・`rejected`（案の名前。再提案を見つける短い語。例「週ごとの切り替え」） |
| `revoke` | 撤回 | `text`（理由）・`quote`・`supersedes`（撤回する判断の ID） |
| `none` | 残す判断の無いカード | `text`・`dec`（カードの id） |

- 任意の欄: `dec`（操縦席のカードの id）・`paths`（関係するファイルの絶対パス）・`supersedes`（置き換える判断の ID）・`affects`（この判断が影響する既存のタスクの id の配列。済のタスクも含む）
- `affects` は操縦席の `tasks` にある id だけを書ける（無い id はコマンドが断る。打ち間違いで見直しから漏れないため）
- 範囲・届け先・対象を変える判断（「ほかの案件の操縦席は消して nix-darwin だけでやる」など）は、`affects` に影響するタスクを全部挙げる。挙げたタスクは、見直して done_when を直すか判断のカードに載せたら、タスクの `reviewed_for` にこの判断の id を足す。足していないタスクは `checks.affected_tasks` に出る（11/21 の R39 で、済の t50 が見直されずに残った）
- ID（`R1` から連番）と日時はコマンドが付ける。形が違う・置き換える判断が有効でないと断る
- 撤回と変更は、元の行を書き換えず、`supersedes` で置き換える行を足す（「本番に入れていい」→「やっぱり待って」は `revoke`。「A で作る」→「B で作る」は `decision` に `supersedes`）。置き換えられた判断は流し直しにも照合にも出ない
- 有効な判断の一覧: `~/.claude/hooks/compaction-keep.py rulings <root>`
