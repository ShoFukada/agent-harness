# メインの作業メモ

cockpit skill の SKILL.md から分けた決まり。作業メモ（`.orca/cockpit/state.md`）を書くとき、hook に「今の順番」が無い・作業メモが大きいと言われたときに読む。

1 ワークスペースのメインは 1 つのチャットで続ける。作業メモ（置き場所は CLAUDE.md の「長いセッション」）には、操縦席だけでは戻せない次だけを書く（R184）。
- 判断の理由（判断の中身は ID で指す）
- 再開時の注意: 頼る検証の対象リビジョン、動いている担当・worker の brief のパスと取り込みの条件（worker の task id は cockpit.json の `tasks[].worker` にあるので書き写さない）

先頭には「今の順番」を置く。窓口が今進める 1〜3 件を、タスク ID と理由 1 行で上から並べる。知らせが続いても次にやることを見失わないための 1 か所で、ほかに順番を書かない。

```
## 今の順番
1. t116 深田さんが 12:07 に負荷を下げてと言った。ほかを止めて先に片付ける
2. t110 worker の結果待ち。届いたら取り込む
```

- hook（compaction-keep.py）が、深田の発言のターンにはこの 3 行にタスクの題を帳簿から添えて流し、担当・worker・Bot・ほかの窓口の知らせと裏の作業の完了のターンには ID と理由だけを流す（R186）。帳簿の `next` は添えない（この順番と食い違う古い `next` が並ぶため）。1 行は 120 字で切る。見出しが無ければ、深田の発言のターンにだけ書くよう 1 行で促す
- 順番を入れ替えたときと、節目（決定・検証・段階が変わったとき）と圧縮の前に書く。帳簿を書いたターンごとには書かない（Stop の hook は作業メモの古さでは止めない）

作業メモは今の状態だけにし、CLAUDE.md の目安（1〜2k トークン）に収める。圧縮のたびに丸ごと流し直されるので、膨らむと要約の枠を食う。
- 時刻つきの行（「- 14:25: 〜した」）を足し続けない。済んだ行は `.orca/cockpit/state.history.md` の末尾へ移す（history は流し直さない。経緯を探すときに読む）
- 「今の順番」の下は Compact instructions の見出しで、いまの値に書き換える。「未完了の項目と次の一手」には、まだ済んでいないことだけを残す
- 8KB を超えると、Stop の hook がターンの終わりに削るよう促す
