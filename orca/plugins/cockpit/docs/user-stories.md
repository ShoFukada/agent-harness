# 操縦席のユーザーストーリー

利用者は受託開発の TL と PM を兼ね、10 本前後の案件を同時に動かす。案件ごとに Orca のワークスペース（本線）があり、窓口のエージェントの下で、仕事ごとの担当（チャット）とコードを書く worker が動く。

操縦席は、利用者の頭を判断にだけ使うための画面。左のディスプレイに置く窓（全案件）と、Orca の右のサイドバーのパネル（前面の案件 1 つ）に、同じコードで出す。ストーリーの元は、利用者と決めた 19 本（U1〜U19）とカード 8 種類。ここには窓とパネルが受け持つ分と、その受入の条件を書く。

## 設計の原則
| 原則 | 中身 | 元の発言 |
|---|---|---|
| P1 私の番は 1 か所 | 判断・許可・送る文面は窓のカードにだけ出す。Bot の「Needs you」や orchestration の gate には置かない。どこで答えても帳簿（`cockpit.user.json`）で 1 回だけ処理する | 「提案書を作る時だけ orca のチャットみるってなんかなあ / それ以外は置物ってことだよね」（11/21） |
| P2 期限の軸だけを目立たせる | 期限順の 1 列と今の線。朱は期限を過ぎた票の文字だけ（24 時間以内は太字）。種類は語で示す。既定は明るい地 | 「ちょっと多すぎる、こんなにあっても流石に管理できない」（11/11）、「黒だと入ってこない」（11/16） |
| P3 会話は担当のチャットで | カードの中に会話の欄を持たない。どのカードからも担当を 1 回で開く | 「それぞれのカードの形とかももっと考えたい」（11/21） |
| P4 取りこぼさない | 見ていない案件・読めていない経路があれば「何もしなくてよい」と出さない。押した操作は受け取り待ち → 受け取ったが見える | |
| P5 サイドバーと同じ名前・同じ状態 | 仕事の表示名と状態を、窓の「案件の今」と Orca のサイドバーでそろえる | 「この辺もできる限りいい感じに出るようにしてね」（11/21） |

## カード
| 種類 | いつ | 中身 | 返答 | 件数 |
|---|---|---|---|---|
| 詰まり | 担当が質問・許可待ち・停止 | 担当と理由、止まってからの時間、私が答えれば進むか | 担当と話す・端末を開く | 数える |
| 許す | push・本番・データの変更の前 | 対象（commit など）・影響・戻し方 | 許す・この案件では任せる・止める | 数える |
| 決める | 設計・要件・費用・言い方が分かれる | 何のため・なぜ今・決めるための情報・選択肢とおすすめ・返事が無いとき | 数字で選んで Enter・担当と話す・別の答え | 数える |
| 送る前 | 顧客か社内へ出す文面ができた | 宛先・送る見た目の本文・元の連絡 | コピーしてスレッドを開く・送った・担当と直す・送らない | 数える |
| 見て | 任せた仕事の出来上がり | 依頼の原文・見てほしい点 1〜3・確かめた結果・差分 | これでよい・直してほしい（担当と話す）・開く | 数える |
| 届いた | 連絡が拾われた | 送り主・原文・聞かれていること・振り分け先 | 担当と話す・返事は要らない・元の連絡を開く | 数えない |
| 話し中 | 担当と会話で作っている | 最後のやり取り・次に待つもの | 続きを話す | 数えない |
| 報告 | エージェントが決めた・済ませた | したこと・理由・戻し方 | 戻して・受け取った | 数えない |

状態の移り変わり: 私の番 →（決める・許す・送った）→ 受け取り待ち → 窓口が受け取る → 片付いた。担当と話すを押すと話し中になり、担当が書き換えてバージョンが上がると私の番に戻る。送ったカードに `awaiting` があれば顧客待ちになり、催促の日を過ぎると朱になる。

## 窓とパネルが受け持つストーリーと受入の条件

### U12 朝いちばんに、全案件の私の番を 1 列で上から片付ける
- 全案件の私の番が、止まっている → 期限切れ → 今の線 → 今日 → 明日 → 今週 → それより先 → 期限なし の順に 1 列で並び、票に案件の名前が付く
- 上の帯に、全案件の私の番の合計と 5 種類の内訳（詰まり・許す・決める・送る前・見て）。届いたは「数えない」で区切って後ろに出す
- 案件を 1 つ選ぶと、その案件の票だけに絞り、票から案件の名前を外す
- 操縦席の無い本線と、読めていない経路（`routes` の失敗・未読・既定 2 時間より古い）は「見ていない」と数を出す。見ていないものがあるときは「何もしなくてよい」と出さない
- 決めたら同じ列の次の票が開く。10 秒の間は操作ごとに「元に戻す」が残る（続けて決めても前の操作を戻せる）
- おすすめのある決めるは、おすすめを選んだ状態で開き、「おすすめで決める」を 1 回押せば決まる。Enter はおすすめのままでは決めない（続けて押して 2 枚決めないように）。選択肢のある許す・詰まりは戻せない操作を含むので、選ぶまで押せない
- 別の答えを開いている間は、その文だけで決める。文が空なら押せない
- 決めるの票は、選択肢を何のため・なぜ今の直後に置き、決めるための情報（5 欄）はその下に置く
- 期限は 1 列の見出しと重ねない。今日の票は時刻だけ、明日の票は「明日 18:00」と出す
- 案件の列には、止まっている・期限切れ・今日・話し中の件数を出す。見ていないものの一覧は上の帯の「見ていない n」から開き、案件の列には重ねない

### U1 カードからその仕事の担当にそのまま聞く
- どのカードにも「担当と話す」がある。押すと、カードの id・種類・題・何のためを引いた書き出しをクリップボードに入れ、担当の端末を前に出す。担当がチャットなら、そのチャットのあるワークスペースを前に出す
- 押したカードは話し中に移って件数から外れ、窓口の端末に「担当と話す d21」を載せた合図が届く
- 担当がチャットのときは、知らせに開くタブの名前（「<仕事の名前>（担当）」）を出す
- 話す相手は、カードの仕事に担当がいれば担当、いなければ案件の窓口。票を開くと「話す相手」と担当の状態（作業中など）が見える

### U8 詰まった担当に気づき、私が答えれば進むかを知る
- Orca で止まった worker は、窓口が書かなくても詰まりの票になり、先頭の「止まっている」に入る。題は「「仕事の題」が許可待ち」の形で、仕事の題（サイドバーと同じ）を先にする。題に仕事の名前が入っている票は、上の行に同じ名前を重ねない
- 許可待ち・返事待ちは「答えれば進む」、落ちた・ログイン切れは「私では直せない」と分ける
- 窓口が書いた詰まりと同じ仕事（タスクか担当の端末）なら、2 枚に重ねない

### U13 案件に入ったら、5 秒でその案件の今をつかむ
- 案件を選ぶと、右（狭い幅では「案件の今・待ち」の切り替え）に、次の節目（あと何日）と、仕事ごとの状態（私待ち・止まっている・作業中・顧客待ち・未着手・済）・次にやること・担当が出る。私待ちが先
- パネルは前面の案件 1 つで、同じ「案件の今」を出す。Orca の下の帯に前面の案件の「私の番 n」を出し、期限 24 時間以内があれば danger の色にする

### P5 サイドバーと同じ名前・同じ状態（追加の要件）
- 仕事の表示名は 20 字までで、何の仕事かが先頭で分かる日本語。超えると `checks.long_names` に出る
- `window/state.ts` の `jobs[].orca` に、表示名・Orca の状態（私待ちは `in-review` と未読の印、作業中・止まっている・顧客待ちは `in-progress`、未着手は `todo`、済は `completed`）が出る。窓口はこれに合わせてサイドバーを書き換える

### U7 戻せない操作だけを押して許し、決まった種類は任せる
- 許すの票に、対象（commit の範囲など）・影響・戻し方が出る。「この案件の <種類> は任せる」で、許したうえで以後を任せられる
- 担当が対象を書き換えてバージョン（`rev`）が上がると、前に押した許可は無効になり、もう一度私の番になる

### U6 任せた仕事は出来上がりだけを見る
- 見ての票に、依頼の原文・見てほしい点・確かめた結果・開くボタンが並ぶ。「これでよい」と「直してほしい（担当と話す）」
- エージェントが決めた小さいことは報告の票に理由と戻し方つきで出て、項目ごとに「戻して」がある

### U10 送ったら、知らせる手間なしに済にする
- 送る前の票は、宛先と改行を保った本文を送る見た目に近い枠で出し、「コピーしてスレッドを開く」がある
- Teams・メール・手で済ませたものは「送った」を押す。Slack で送ったものは見張りが読み取って済にする（見張りは窓の外）

### U9 届いた連絡が拾われている
- 届いたの票に、送り主・原文・聞かれていること・振り分け先が出る。件数には数えない
- 経路が読めていないときは「Teams 病院の情報部: 11/21 08:00 から読めていない」のように、いつから読めていないかを出す

### U19 送ったら回答待ちとして追う
- 顧客待ちの列に、誰の何を待ち、いつから待ち、回答で何を再開するかが出る。催促の日を過ぎたら朱になり、hook の `checks.remind_due` にも出る

### U15 片付いたことを読み返す
- 片付いたの列に、14 日分が新しい順に並び、採った返答（「決めた: …」「許した」「送った」）・日時・受け取り待ちか受け取ったかが読める。それより古いものは `cockpit.archive.json` に残る

### U18 割り込みで期限が変わったら反映する
- 窓口がカードやタスクの期限を書き換えると、1 列の位置がその場で変わる（窓は書かれた期限だけを見る）

## 窓とパネルでは満たせないもの
| ストーリー | 満たせないこと | 理由と受け持ち |
|---|---|---|
| U1 | 担当のチャットのタブそのものを前に出す | Orca に既存のチャットを前に出す API が無い。今はチャットのあるワークスペースを前に出し、タブは利用者が選ぶ |
| U1 | 作業中の担当の脇で fork が答える | チャットが受け持つ |
| U7 | 「18 時まで本番も任せる」のように期限つきで任せること | 窓口が期限を持つ形が決まっていない |
| U8 | 今日終わるはずの仕事が動いていないことの検知 | 終わる見込みをデータに持っていない |
| U13 | 終わる見込みと、前に見たときから変わったこと | 同上。見た時刻を持っていない |
| U15 | 片付いたものを案件と仕事ごとの見出しで並べる | 今は新しい順の 1 列（絞り込みで案件ごとには読める） |
| U2〜U5・U11・U14・U16・U17 | 担当を立てる・顧客メモ・モデルの切り替え・圧縮・運用保守の流れ・定例の 1 枚・説明のページ・設計図 | 窓口・orchestration・Bot・hook が受け持つ。窓は結果のカードを出す |

## 採らなかったもの
- カードの中の会話の欄（前の「話したいこと」と `claude -p` のすぐの回答）: 会話は文脈を持つ担当が答えないとずれる（U1）。担当のチャットで話す形にした
- 大タスク → タスク → 確認とたどること（前の全体のタブ）: 朝の 1 列で上から片付ける使い方に合わない。案件の今の仕事の行で足りる
- 窓に別の情報（PR・CI・カレンダー）を足すこと: 元の情報は各ツールにあり、同じ管理を重ねない
- メモリの数字: 判断を変えるのはエージェントの数で、細かい数字は負荷になる
