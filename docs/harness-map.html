1背景と前提

agent-harness は、Orcaで複数のコーディングエージェントを並べて動かすときに、深田さんが判断と大事な確認にだけ頭を使えるようにする道具の集まりです。案件ごとの窓口のエージェントが作業を進め、深田さんは「自分の番」のものだけを左のディスプレイの窓で片付けます。

前の見取り図（artifact 2b3a7062）は別の席のアカウントで公開したもので、今の窓口からは読めません。その後に設計が3か所で変わったので、今の実物から描き直しました。

  • 依頼の帳簿: 深田さんの依頼を受けた時点で帳簿に載せ、済の条件と証拠（mainに入ったcommit・公開したページ・深田さんの操作）がそろったときだけ済にする（帳簿の形の版3）
  • 待ちと済を事実から決める（R204）: タスクに手で書く状態は「済んでいない」と「完了」だけ。止まり・待ち・未着手は、カード・操作・workerの様子・待ちの理由・日付から判定の関数が決める
  • 知らせを1本にする（R191）と席の切り替え（R205）: エージェントの会話へ届ける知らせは orca orchestration send だけ。利用枠の上限では席を替え、動いているclaudeを今の席へ移す

3部分ごとの図

3.1役と、誰が誰を起こすか

窓口は担当と自分で立てたworkerのcoordinator、担当は自分のworkerのcoordinatorで、止まれば必ず1つ上が起こされます。

細部
  • 帳簿（操縦席）を書くのは窓口だけ。担当とworkerは書かず、深田さんに決めてほしいことは窓口に send で届け、窓口がカードにする
  • 担当は仕事が終わるまで残り、workerは1つのworktree・1つのTaskごとに立てて畳む。1つのworktreeにworkerは1人
  • 担当とworkerがcoordinatorに送るのは、完了・停止・深田さんの判断の依頼・調整の4つだけ（worktree-flow skillの references/worker-rules.md）
  • 窓口自身が止まったことは、会話の外の見張り（stallwatch、5分おき）が通知と窓の帯で知らせる

3.2知らせの経路

エージェントの会話へ届ける知らせは orca orchestration send の1本で、宛先は窓口のRun・担当とworkerの今のDispatch・カードの相談のhandleの3つです（R191）。

細部
  • チャットには1通ずつのメッセージで届き、端末には orca orchestration check を打つよう促す1文が届く。受け手は起こされたときだけ読み、見張りのスクリプトや check の繰り返しはしない
  • Orcaの外のプロセス（窓・見張り）は送り主の端末を持たないので、AIを動かさない郵便受けの端末（タブ名「操縦席｜郵便受け」）を --from にする。launchdからは bin/cockpit-mail を使う
  • 担当は ask を使わず、窓口は担当に reply しない（入れ子のcoordinatorには reply が届かない）
  • 決まりの本文は worktree-flow skillの references/notify.md「知らせの経路」
  • 窓の操作と窓からの質問が窓口に届く順番は、詳しい図の5.2・5.3

3.3帳簿を書く道具と読む道具

置き場所ごとに書き手は1種類だけで、状態は誰も手で書かず、窓・パネル・hook・書く道具がみな同じ state.ts の判定を読みます。

細部
  • 帳簿をWrite・Editで書こうとするとhookが断り、書く道具を案内する。書く道具は型・参照・rev・仕分け・言い回しを検査し、通らなければ書かずに理由を返す
  • 窓口も状態は node ~/.config/agent-harness/orca/plugins/cockpit/window/state.ts <root> の出力で読む（2026-11-16に、手書きの状態を数えて済んだ依頼2件を作業中と思い込んだため）
  • hook（periodic-reminder.sh・compaction-keep.py）は、判定の checks から直させることを窓口の発言のたびに流し、圧縮のあとに判断の記録と発言の原文を流し直す
  • 欄と書き手の一覧はcockpit skillの references/schema.md「ファイル」。ファイルごとの読み書きの図は詳しい図の3.2

3.4待ちと済を事実から決める形

窓口が手で書くのは「済んでいない（open）」と「完了（ok）」だけで、それ以外の状態は図5の順に事実から決まります（R204）。

細部
  • 待ちは4種類だけ書ける: 外の相手の返事（person）・出来事（event）・日付（date）・空き枠（slot）。深田さんを待つものは書かず、頼むカードからタスクを指す
  • 待ちが解けたことは、発言・知らせ・操作・議事録を指して wait.met[] に書く。会話で「届いた」と言うだけにしない
  • 仕事の状況の文（streams[].status）は、元の事実が変わったのに書き直さないと書く道具が断る。窓は古い文の代わりに事実の文を出す
  • タスクを済にしたら、同じ仕事と前提でつながる開いたタスクを同じ書き込みで直すか、関係ないと確かめて unaffected に並べる
  • 深田さんの確認が要る依頼（check: true）は、今の版のカードに押された「承認」の操作も証拠に要る
  • 判定の各行の窓の文と待ちの4種類は詳しい図の4.6、書く道具が断る規則の一覧は6章

3.5席の切り替え

上限に当たった席は1分以内に空いている席へ替わり、Orcaの中のclaudeは会話とworkerの設定を保ったまま今の席へ移ります（R205）。

細部
  • 使用量はOrcaが読んでいる各席の値（orca account list --json）だけで判断し、トークンやKeychainには触らない
  • 端末は、移す前に元の会話id・引数・workerの設定を記録に残してから /exit を送り、同じ端末に env CLAUDE_CONFIG_DIR=<今の席> claude … --resume <会話 id> を打つ。Dispatchは端末に結び付くので残る
  • Dispatchを持つチャット（担当）を止める前に、窓口のRunの受信箱へ「席の切り替えで止めた。立て直さない」を1通送る
  • 全部の席が上限なら切り替えず、最初に戻る席と時刻を帯に出す。そのあいだは新しいworkerを立てない
  • Orcaの設定「When you switch accounts while Claude is running in terminals」は「Never restart」（値はkeep）にしておく（「Always restart」だと端末が開き直されてDispatchがlostになる）
  • 見張りの知らせが帯と窓口に届く経路は詳しい図の5.5

3.6見張りと片付け

モデルを呼ばない4つのプロセスが、Orcaと窓口の外から、止まったものと使い終わったworktreeを見つけ、図1の経路8で知らせます。

道具いつ拾うもの知らせる先
bin/stallwatchlaunchd・数分おきOrcaそのもの・各ワークスペースの窓口・窓・定時ジョブの停止macOSの通知と窓の上の帯（帯の書き手はこれ1つ）
bin/account-failoverlaunchd・1分おき利用枠の上限と、古い席で動くclaude（3.5）通知と帯（stallwatchが合流させる）

bin/worktree-sweep毎晩取り込み済みで使い終わったworktreeを消し、人が決めるものを一覧にするsweep.json（窓口のhookが自分の下だけ拾う）
